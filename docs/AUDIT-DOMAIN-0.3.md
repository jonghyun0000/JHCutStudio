## 이번 편집 계약

- 삽입/덮어쓰기는 지정한 `.video` 트랙만 조정한다. 다른 트랙의 자막·오디오는 자동 이동하지 않는다.
- 구간 편집은 원본 속도·sourceStart를 유리수로 매핑한다.
- 기존 ease와 페이드가 포함된 구간은 출력 프레임 시점 및 원래 키/페이드 경계에서 값이 일치하도록 linear 키프레임으로 구체화한다. 프레임 사이 연속 곡선까지 비트 단위로 동일하다고 주장하지 않는다.
- 계산·메모리 폭증을 피하기 위해 한 번의 표본화는 36,000개 키프레임을 넘으면 명시적으로 거부한다. 원래 미디어를 변경하지 않는다.
- 수집은 기존 목적지가 있으면 실패한다. APFS 등 지원 볼륨은 새 폴더를 원자적으로 확정한다. ExFAT는 목적지를 배타적으로 예약하고 파일을 배타적으로 생성한 뒤 Project.jhcut을 마지막에 기록하므로, 완료 전 폴더가 잠시 보일 수 있다. 전체 원본을 복사하고 프로젝트의 모든 자산/파생 시퀀스를 보존한다.

## ExFAT 실제 볼륨 후속 수정 및 검증

최종 GUI 수집에서 T7 ExFAT의 `renamex_np(RENAME_EXCL)`가 errno 45 (ENOTSUP)를 반환했다. 기존 임시폴더 테스트는 APFS에서만 실행되어 이 차이를 놓쳤다. 실제 `/Volumes/T7`에서 재현하고 다음을 수정했다.

- 지원 파일시스템의 원자적 이동은 유지한다. ENOTSUP인 경우 `mkdirat`으로 목적지를 배타적으로 예약하고 `openat(O_CREAT|O_EXCL|O_NOFOLLOW)`으로 생성한 바로 그 파일 디스크립터를 사용한다. 존재 여부 확인 뒤 일반 rename/moveItem하는 경쟁 조건은 없다.
- 최종 목적지의 파일도 열린 동일 디스크립터로 되읽어 SHA-256을 검증한다. `Project.jhcut`은 모든 미디어와 부가 파일 뒤에 작성한다. ExFAT에서 폴더 전체의 원자적 공개는 보장하지 않으며 중단/전원 장애 시 미완료 폴더가 남을 수 있다.
- 취소/실패 시 직접 생성했고 식별자가 일치하는 파일만 제거한다. 디렉터리는 비어 있을 때만 rmdir한다. 외부 프로세스가 추가한 파일은 보존한다.
- ExFAT는 빈 파일에 임시 inode를 주고 쓰기 후 fsync/close 때 최종 inode로 바꾼다. 취소 경로에서도 fsync 후 열린 fd에서 식별자를 다시 받아 본인이 쓴 파일만 정리한다.

실제 T7 회귀 4개를 추가했다: 휴대용 수집/중복 제거/원본 제거 후 읽기/기존 목적지 보호, 두 수집 요청을 동시에 12번 경쟁시켜 항상 한 요청만 성공하는 검증, 원본 누락 실패 정리, 64MB 미디어가 목적지에 1MB 이상 쓰인 뒤 취소하면서 외부 파일을 보존하는 검증. 테스트 임시 폴더는 작업공간의 볼륨에 생성하고 끝나면 정리한다.
