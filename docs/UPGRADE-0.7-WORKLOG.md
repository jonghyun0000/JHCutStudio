## 1. 긴 영상 인식 체크포인트와 이어하기

**구현**
- `Services/TranscriptionCheckpoint.swift`: 구간(기본 5분)마다 결과를 `Application Support/JHCutStudio/Checkpoints/<키 해시>/window-NNNNN.json`에 원자적으로 저장. 키 = 프로젝트 ID·클립 ID·**실행 시점 원본의 전체 SHA-256**·원본 범위·구간 길이·언어·채널·힌트·정확도 옵션·모델 SHA-256·엔진 버전·무음 건너뛰기 여부. 하나라도 다르면 재사용하지 않는다.
- 원본 해시는 `MediaFingerprintCache`로 크기·수정 시각·inode·앞뒤 64KB가 같을 때만 재사용하고, 바뀌면 전체를 다시 해시한다.
- 체크포인트는 문서를 읽거나 쓰지 않는다. 결과는 기존의 스냅샷 비교(`project == snapshot`) 뒤 한 번의 일괄 명령으로만 타임라인에 들어간다.
- 손상된 구간 파일·다른 키의 manifest·클립 범위를 벗어난 자막은 무시하고 해당 구간만 다시 인식한다. 체크포인트 쓰기 실패는 인식을 실패시키지 않고 상태 문구로 알린다.
- UI: “긴 영상 이어하기” 토글, 선택 클립의 완료 구간 수, “체크포인트 삭제”, “처음부터 다시 인식”, 진행 중 “구간 n/m · 원본 시각 · 재사용 · 남은 예상 시간”. 남은 시간은 이번 실행에서 실제로 인식한 구간이 생긴 뒤에만 표시한다.

**이 과정에서 찾은 기존 결함 — 음성 추출 비결정성**
- 같은 90초 음성을 8번 인식하자 8가지 결과(자막 20/22개, 시각 ±0.02초)가 나왔다. 같은 WAV로 whisper-cli만 반복하면 1·6스레드 모두 4/4 동일했으므로 원인은 앱의 추출 단계였다.
- 추출이 리더에 16kHz 변환을 맡기고, 버퍼마다 반올림한 시각으로 다시 배치했다. 시각이 실행마다 한 샘플씩 흔들려 음성 중간에 샘플이 끼거나 빠졌다(10초 추출 6회 중 1회는 16,372샘플이 최대 4,791 차이).
- 수정: 원본 샘플레이트로 디코딩 → 2ms를 넘는 실제 공백만 채우거나 겹침을 제거 → 고정 16,384프레임 블록으로 직접 16kHz 변환 → 16비트 양자화도 직접 수행.
- 수정 후 같은 90초 음성 8회 인식 결과가 모두 동일했다.
- 남은 차이: Apple AAC 디코더 자체가 실행마다 부동소수 최하위 차이를 낸다(원본 레이트 10초 디코딩 5회 비교, 최대 2.1×10⁻⁷ = 16비트 한 단계의 0.68%). 16비트로 바꾸면 16만 샘플 중 몇 개가 1LSB 다를 수 있다. 위 8회 시험에서는 인식 결과에 영향이 없었지만, 모든 입력에서 비트 단위 동일을 보장하지는 않는다.

## 2. 대본 기반 자동 정확도 평가

**구현** — `Services/TranscriptEvaluation.swift`, 편집기 `App/EditorQuality.swift`, 자막 패널 “대본으로 정확도 평가”
- 영상 옆 같은 이름의 `.srt`(우선)·`.txt`를 읽는다. 인코딩은 기존 자막 디코더(UTF-8/UTF-16 BOM/CP949) 사용. 대본 파일과 원본 폴더에는 쓰지 않는다. 보고서는 `Application Support/JHCutStudio/Reports/`에 JSON + Markdown.
- 언어별 정규화: 공통 NFKC·소문자·문장부호/기호 제거. CER은 공백을 뺀 글자. WER 단위는 한국어 어절, 영어 공백 단어, 일본어 NLTokenizer(분할기 의존임을 보고서에 표기).
- 문장 정렬: 1:1·1:2·2:1·1:3·3:1 묶음을 허용하는 단조 정렬, 유사도 0.5 이상만 일치. 누락(대본에만)·과잉(자막에만)·불일치 문장 목록. 긴 대본은 대각선 밴드로 제한하고 도달하지 못하면 전체 표로 재계산.
- 시간 오차: `.srt` 대본일 때만. 자막을 연결 정보로 원본 시각으로 환산해 시작·끝 평균/중앙값/최대, 0.5초 이내 비율.
- **평가 불가**: 대본이 없으면 수치 없이 “평가 불가 · 대본 없음”. 시간 없는 `.txt`인데 클립이 원본의 98% 미만만 쓰면 누락이 과대 계산되므로 평가하지 않는다. `.srt`는 클립 원본 범위 안의 문장만 비교.

**검증** — `bash Scripts/test-evaluation.sh` → `Artifacts/Upgrade-0.7/Evaluation/checks.json` **42/42 통과**
- 순수 지표: 치환·삭제·삽입 개수, 한국어 띄어쓰기 무시, 영어 대소문자, 일본어 분할, 문장 분할/병합, 누락·과잉 검출, 시간 오차, 평가 불가 경로 4종.
- 실제 Whisper + 문장별로 합성해 **배치 위치를 정확히 아는** 음성(정답 `.srt` 시각 = 각 문장 클립의 배치 구간이며, 음성 앞뒤의 무음이 포함됨):

| 언어 · 음성 | CER | WER | 누락/과잉 | 시작 오차 중앙값 |
|---|---:|---:|---:|---:|
| 한국어 · Yuna | 0.0% | 0.0% (어절) | 0/0 | 0.32초 |
| 일본어 · Kyoko | 15.3% (59자 중 치환5·삭제2·삽입2) | 16.7% | 0/0 | 0.32초 |
| 영어 · Samantha | 0.0% | 0.0% | 0/0 | 0.03초 |

이 수치는 Mac 합성 음성 기준이며 실사 녹음의 정확도가 아니다. 시작 오차에는 합성 음성 자체의 앞 무음 길이가 섞여 있다.
- 처음 실행에서 정렬 점수가 유사도 낮은 쌍도 짝을 짓게 되어 있어 누락·과잉이 흡수되던 결함을 테스트가 잡았고, 점수를 “유사도−기준값”으로 바꿔 수정했다.

## 3. 문장별 언어 감지 고도화

**구현** — `Services/SentenceLanguage.swift`, `CaptionMetadata`에 `clipLanguage`·`languageConfidence`·`languageManual`·`languageNeedsReview`(문서 호환성 허용 목록에 등록)
- 한글·가나·라틴 문자 비율(서로 겹치지 않는 문자 체계)을 먼저 보고, 나머지는 ko/ja/en으로 제한한 NLLanguageRecognizer 확률로 판단. 글자 4개 미만(“OK”, “네”)·한자만 있는 문장·확률 0.6 미만은 **추측하지 않고** 클립 대표 언어를 쓰며 “언어 확인 필요”로 표시.
- 클립 대표 언어(Whisper)와 문장 언어를 따로 저장. 번역은 문장 언어별로 묶어 실행하고 완료 문구에 구성을 표시(예: “문장별 원문 언어 영어 2 · 한국어 6”).
- 자막 목록마다 언어·감지 신뢰도·확인 필요 표시와 “언어” 메뉴(직접 지정 / 자동 감지로 되돌리기). 한 번에 실행취소. 직접 지정한 문장은 재인식(교체 모드)에서도 보존.

**함께 고친 결함**
- Whisper가 따옴표 하나만 있는 구간을 내면 빈 자막이 생겼다 → 글자·숫자가 없는 조각은 자막으로 만들지 않음.
- 영상 트랙이 오디오보다 20µs 짧은 MP4에서, 파일 전체 길이 클립이 “원본 프레임 범위 밖”으로 렌더링 거부되었다(기존 결함). 부족분이 한 프레임 미만일 때만 사용 가능한 영상을 클립 길이에 맞춰 늘린다. 그보다 크면 기존처럼 거부.

**검증** — `bash Scripts/test-language.sh` → `Artifacts/Upgrade-0.7/Language/checks.json` **20/20 통과**
- 판별기 단위 검사, 한 클립 안에 한국어·영어·일본어·한국어 합성 음성을 이어 붙인 실제 인식, 문장 언어 ≠ 클립 언어 기록, 수동 지정의 저장/재열기·실행취소·재실행, 재인식 보존·중복 없음, 실제 Apple 번역으로 문장 언어별 번역, 한국어 문장은 번역 없이 그대로, 자동 감지 복귀.

**확인된 한계 (추측 아님, 이 시험의 실제 출력)**
- Whisper는 인식 구간마다 언어를 하나만 정한다. 이 시험에서 구간이 한국어로 판정되자 일본어 문장 “こんにちは。今日はいい天気ですね”가 **한글 발음 “곤니지와, 겨와, 이 땡기 대순해”로 받아써졌다**. 텍스트가 이미 한글이므로 문장별 판별기는 이를 한국어로 판정한다. → 7단계에서 음성 구간 단위 재인식으로 보완한다.

## 4. 화자 분리

로컬에 화자 분리 모델이 없고 새 모델 다운로드는 하지 않으므로, **채널 분리라는 물리적 근거가 있을 때만** 화자를 붙인다(whisper.cpp `--diarize`와 같은 원리). 목소리 특징으로 사람을 추정하는 방식은 쓰지 않았다.

**구현** — `Services/SpeakerSeparation.swift`, `CaptionMetadata.speaker/speakerStatus`, `Sequence.speakers`(이름·색, 문서 호환성 등록)
- `channelLayout`: 활성 채널(최대 채널 대비 −10dB 이상)과 채널 간 최대 상관계수. 활성 채널 2개 이상 + 상관 0.5 미만일 때만 “채널이 분리된 녹음”.
- **채널별로 따로 인식**: 분리된 녹음이면 채널마다 Whisper를 돌려 그 채널을 화자 A/B/…로 지정. 분리되지 않았으면 측정값(활성 채널 수, 상관)을 보여 주고 거부. 모노는 비활성.
- **문장별 판정**(기존 자막 대상): 문장 구간에서 가장 큰 채널이 6dB 이상 크고, 그런 문장이 60% 이상이며 우세 채널이 둘 이상일 때만 표시. 아니면 “화자 구분 불확실”로 표시하고 화자를 붙이지 않음.
- 화자별 이름·색 적용(해당 화자 자막 색 일괄 변경), 화자별 자막 트랙으로 나누기. 모두 한 번에 실행취소, 시간·연결 정보는 바꾸지 않음. 번역 자막은 원문의 화자를 이어받음.

**함께 고친 기존 결함 — 채널별 마이크 녹음에서 한 사람의 말이 통째로 빠짐**
- 자동 채널 선택이 가장 큰 채널 하나만 Whisper에 넘겨, 오른쪽 채널의 화자 B 대사가 전혀 인식되지 않았다(자막 4개 모두 화자 A).
- 이제 둘째 채널이 −10dB 이상이고 반대 위상(상관 < −0.5)이 아니면 두 채널을 평균한다. 반대 위상 쌍은 기존대로 한 채널만 사용(생산성 검사의 반대 위상 항목 통과).

**검증** — `bash Scripts/test-speaker.sh` → `Artifacts/Upgrade-0.7/Speaker/checks.json` **20/20 통과**
- 화자 A(Yuna)는 왼쪽, 화자 B(Eddy)는 오른쪽에만 있는 합성 대화: 채널별 인식으로 자막 8개, **말한 사람 기준(내용 대조) 8/8 정확**, 두 화자 모두 존재, 클립 안, 프로필 생성, 저장/재열기, 실행취소/재실행, 이름·색 적용, 트랙 분리 시 ID·시각·연결 유지.
- 두 채널을 평균한 일반 인식에서는 Whisper가 화자 전환을 가로지르는 긴 자막 2개를 만들었고, 문장별 판정은 이를 추측하지 않고 불확실로 남겼다.
- 같은 신호가 양쪽에 있는 녹음: “불확실”, 화자 미지정, 채널별 인식 거부(측정 상관 1.00). 모노: “불가”, 문서 불변.

**확인된 한계**
- 채널별 인식 자막의 시각은 8개 중 4개만 그 화자의 발화 구간 안에 중간점이 있었다. 다른 사람이 말하는 동안 해당 채널은 무음이고, Whisper가 무음을 가로질러 타임스탬프를 늘린다. 7단계 이후 다시 측정.
- 한 대의 폰으로 여러 사람을 녹음한 일반적인 영상(실사 아이폰 영상 포함)은 채널이 분리되지 않으므로 화자 구분을 하지 않는다. 이를 하려면 화자 분리 모델이 필요하며, 모델 설치는 사용자 승인 사항이다.

**회귀** — 생산성 37/37(반대 위상 포함), 자동 자막 17/17, 체크포인트 40/40.

## 7-보완. 비음성 건너뛰기에서 대사가 빠지는 문제 (2026-09-28)

**발견** — 정확도 측정용 구간을 준비하다가, IMG_9211 8:36~8:51의 대화(전체 인식에서는 “바타 플라인가요? — 네, 맞아요” 등)가 건너뛰기 인식에서 통째로 빠진 것을 확인했다. 이 부분은 음성 구간으로 판정돼 Whisper에 전달됐지만, 압축된 오디오 앞부분에서 Whisper가 “[몇일이 없음]”을 만든 뒤 약 13초 동안 아무것도 내지 않았다.

**해결** — `CoverageRepair`(Services/LocalTranscription.swift)
- 압축된 창에서만, 말소리 구간 중 자막이 없는 3초 이상 구간을 **그 구간만 따로**(이전 문맥 없이) 다시 인식한다. “[…]”·가사 줄은 자막으로 치지 않고, 복구한 말이 있으면 그 구간의 괄호 줄을 지운다.
- 앞뒤 문맥은 0.4초로 먼저, 비면 2초로 다시. 실측: 0.4초가 13초 대화를 되살렸고 2초는 놓쳤으며, 반대로 2초가 되살리고 0.4초는 “[놀람]”만 낸 구간도 있었다. Whisper의 무음 판정 임계값을 올리면(`-nth 0.9`) 모두 빈 결과였다.
- 재인식 자막은 시각이 문맥 쪽으로 번지므로 **빈 구간 안으로 잘라** 넣는다. 처음 구현은 이웃 자막과 겹친다고 버려 실제 대사를 잃었다.
- 비용 제한: 분류기가 0.6 이상으로 확신한 말소리가 2.5초 이상 있는 구간만, 창당 최대 4개. 처음처럼 모든 빈 구간을 재시도하면 공연 영상(IMG_0140)에서 건너뛰기가 전체 인식보다 느려졌다(73초 대 52초). 압축되지 않은 창(말소리가 대부분인 영상)은 재시도하지 않아 전체 인식과 결과가 같다.
