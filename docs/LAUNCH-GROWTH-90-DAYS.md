# JH CUT Studio — 출시 후 90일 성장 운영 계획

작성·공식 규칙 확인: 2026-10-15. 상태: **준비 문서, 실행 결과 아님**. 담당: 프로젝트 유지보수자. 게시·연락·유료 집행·자동 수집을 이 문서로 실행하지 않는다.

## 시작 조건과 목표

목표는 Mac 개인 창작자가 설치하고 첫 영상을 출력한 뒤 다시 사용할 수 있게 만드는 것이다. GitHub 스타 **100 → 1,000 → 3,000 → 10,000**은 장기 성과 이정표다. 날짜별 달성 약속이나 90일 보장 수치가 아니다. 출시 준비 완료와 스타 달성은 별도로 보고한다.

현재는 개발판 0.7.0 build 8이다. 서명·공증된 공개 설치 파일, 실제 Release 다운로드, 다른 Mac 설치 검증, 다운로드 사이트와 공개 데모가 아직 완료되지 않았다. Developer ID·공증 설정과 다른 Mac은 사용자가 아직 준비하지 못했다고 확인했다. 최신 제품 판정은 [출시 준비 현황](RELEASE-READINESS.md)을 기준으로 한다. 이 계획은 성능·정확도·사용자 수를 증명하지 않는다.

**Day 0**은 아래 조건을 충족한 실제 공개 출시일로 기록한다. 준비 기간을 출시 후 사용 실적으로 계산하지 않는다. 외부 조건을 기다리는 동안 샘플·튜토리얼·기여 문서·사이트 미리보기·소개 초안을 완성한다.

- 출시 차단 결함 판정과 편집·저장·복구·출력 증거, 알려진 문제 공개.
- 공개 소스와 LICENSE·외부 고지·개인정보 검토, 공개 CI 실제 실행.
- 태그/커밋에 연결된 설치 파일, 서명·공증·staple·Gatekeeper 결과, SHA-256.
- 다른 지원 Mac에서 최초 설치·업데이트·샘플 편집·저장·출력.
- 버전·크기·SHA가 맞는 실제 다운로드 사이트. 다운로드에 로그인·Star 요구 없음.
- 재배포 가능한 결과물/프로젝트 3개, 실제 30–60초 데모, 첫 출력 튜토리얼.

아직 조건을 채우지 못한 상태에서 개발 현황을 공유한다면 반드시 “개발판/출시 준비 중”이라고 설명한다. 위험한 우회 설치를 일반 사용자의 정상 설치 안내로 삼지 않는다.

## 운영 주기와 작업 한도

유지보수자가 주 1회 같은 요일에 기록한다. 실제로 맡을 사람이 없는 작업은 담당 미정으로 남긴다. 제안 운영 한도는 주 1개 성장 실험, 주 1개 튜토리얼 또는 재현 사례이며, 장애 대응이 생기면 홍보부터 줄인다. 같은 문구를 여러 커뮤니티에 반복 배포하지 않는다.

## 측정 사전과 개인정보

기본 계획은 **앱 사용 정보 자동 수집 없음**이다. 이 문서 때문에 앱/사이트에 분석 SDK, 설치 ID, 쿠키, 이벤트 전송을 추가하지 않는다. 웹 호스팅과 GitHub 자체 로그는 앱 텔레메트리와 구분하고, 사이트가 정해지면 실제 서비스의 처리와 보존 범위를 개인정보 안내에 명시한다.

| 지표 | 정의·수집 방법 | 해석 제한 |
|---|---|---|
| 스타 | 같은 날짜/UTC 시각의 저장소 전체 stargazers_count와 이전 관측 대비 순증 | 사용·설치·만족·정확도 지표 아님. API 오류는 결측이며 0으로 바꾸지 않음 |
| 다운로드 | 공개 Release별 **설치 파일** asset ID의 download_count 차이. 체크섬/소스/샘플은 별도 | 재시도·반복 다운로드·자동 요청 포함 가능. 고유 사용자·설치·활성 사용자 수로 부르지 않음. 자산 교체 시 새 ID로 분리 |

| 재사용 | 동의한 참여자가 첫 성공 뒤 14일 이내 다른 날에 두 번째 프로젝트를 편집·출력했다고 자발적으로 답한 건 | 동의한 관찰 대상만의 응답. 전체 사용자 유지율로 일반화하지 않음. 미응답=이탈 아님 |

GitHub의 [Release assets API](https://docs.github.com/en/rest/releases/assets)는 자산별 download_count·크기·다운로드 URL 등을 제공한다. 이를 설치 사용자 수로 바꾸지 않는다. [Traffic API](https://docs.github.com/en/rest/metrics/traffic)는 짧은 최근 기간의 방문/클론 통계를 제공하므로 필요할 때 권한 있는 유지보수자가 주 1회 보존한다. 기간별 unique 값을 더해 90일 고유 사용자라고 부르지 않는다. 토큰·개별 방문자 정보를 공개 보고서에 넣지 않는다. 공식 문서 확인: 2026-10-15.

자발적 피드백은 버전, 선택한 작업, 완료/실패 단계, 선택적인 OS/CPU 종류 정도로 시작한다. 원본 영상·음성·자막·개인 경로·전체 로그·이메일을 필수로 요구하지 않는다. 공개 이슈의 공개성을 안내하고 민감한 자료를 올리지 않게 한다. 개인별 재사용 응답을 연결하려면 그 목적·기간과 자발적 동의를 먼저 확인한다.

비공개 자발적 조사 기록의 제안 보존 한도는 수집일부터 90일이며, 이후 식별 가능한 연결 정보를 지우고 비식별 집계만 남긴다. 실제 모집 전에 이 기간·담당·삭제 요청 경로를 확정해 안내한다. 공개 GitHub 이슈와 외부 플랫폼 자료는 같은 방식으로 삭제를 보장할 수 없음을 설명한다. 이미 운영 중인 수집 체계가 있다는 뜻은 아니다.

나중에 자동 앱 측정이 꼭 필요하면 별도 구현/검토가 필요하다. 기본 꺼짐, 거부해도 핵심 기능 사용, 최소 이벤트와 보존 기간·삭제 방법 공개가 조건이다. 제안 예시는 앱 버전·작업 성공/실패 범주뿐이며 영상명·자막·전체 경로·광고 ID·지속 추적 ID는 제외한다. 이 계획은 동의 화면/수집 서버를 구현하거나 적법성 판정을 완료한 것이 아니다.

## 공식 채널 규칙과 실행 조건

아래는 **2026-10-15 공식 출처에서 확인한 내용**이다. Reddit 커뮤니티 응답은 검색 도구에서 약 3주 전 크롤로 표시되므로 게시 당일 원문과 고정 공지를 다시 확인한다. 규칙·계정 자격·개별 게시 허가를 확인하지 못하면 실행하지 않는다. 대상별 사용자 승인 없이는 게시/DM/메일/모더레이터 연락을 하지 않는다.

| 후보 | 확인 근거와 적용 | 현재 판단 |
|---|---|---|
| 자체 저장소/사이트 | [GitHub 이용 정책](https://docs.github.com/en/site-policy/acceptable-use-policies/github-acceptable-use-policies): 스팸·가짜 상호작용·자동 스타·보상 기반 부정 참여 금지. 다른 저장소 이슈를 광고판으로 쓰지 않음 | 제품 자료를 준비할 수 있음. 공개 반영은 기존 사용자 승인 범위와 최종 검토에 따름 |
| Show HN | [Show HN](https://news.ycombinator.com/showhn.html): 직접 시도할 수 있는 작업, 제작자 참여, 진입 장벽 최소화. 랜딩 페이지만 제출하지 않음. [HN 지침](https://news.ycombinator.com/newsguidelines.html)은 생성/AI 편집 텍스트와 자동 게시, 표·댓글 요청을 금지 | 실제 사용 가능 뒤 **제작자가 직접 쓴 글과 답변**만 후보. 이 AI 초안을 복붙하거나 AI로 다듬어 제출하지 않음 |
| r/macapps | [공식 커뮤니티 규칙](https://www.reddit.com/r/macapps/about/rules.json): 개발자 관계 공개, 커뮤니티 자격·템플릿·승인 절차, 제한된 자기 홍보, 공식 배포 링크. 미자격은 지정 megathread 조건 확인 | 계정 자격 미확인. 월별 스레드/PCP 조건과 게시 승인 공지 재확인 전 보류. 카르마 확보를 위한 무의미한 댓글 금지 |
| r/opensource | [공식 커뮤니티 규칙](https://www.reddit.com/r/opensource/about/rules.json): 공개 저장소의 OSI 라이선스, 적합한 flair, 과도한 자기 홍보 금지. AI 생성 콘텐츠 금지 명시 | 이 초안 게시 금지. 공개 라이선스 확인 뒤 제작자가 직접 작성한 내용만 검토 후보 |
| 한국어 창작자 커뮤니티/기타 SNS | 특정 대상이 아직 정해지지 않아 규칙 확인 미완료 | 대상 URL·홍보 게시판/빈도·외부 링크·제작자 공개·AI 규칙·사용자 승인 범위를 기록한 뒤 선택 |

규칙 요약은 게시 허가가 아니다. 읽히지 않는 규칙/명확하지 않은 자격은 승인된 범위에서 운영자에게 확인하거나 해당 채널을 제외한다. 유료 광고·인플루언서 계약·언론 연락은 이 계획에 포함되지 않는다.

## 주간 기록 양식

아래 빈칸은 실제 관측 후 채운다. “없음/미수집/결측”을 서로 구분한다. 공개 보고에는 집계와 동의된 인용만 넣고, 민감한 원본은 저장소에 넣지 않는다.

```text
기간 / 관측 시각(UTC):
담당 / 앱 버전 / tag·commit / 공개 asset IDs:
실행한 실험 ID / 대상 채널 URL / 승인 범위 / 규칙 재확인일:
승인 근거(사용자 지시의 날짜·범위) / 실제 게시자 / 자동 게시 없음 확인:
가설 / 바꾼 한 가지 / 실제 공개 콘텐츠 URL:
스타 전체·순증 / 설치 파일 다운로드 건수(자산별):
자발적 첫 출력 성공·실패·미응답 / 분모 / 표본 한계:
자발적 재사용 응답 / 관찰 기간·분모 / 미응답:
출시 차단 결함 / 해결·재발·미해결 / 외부 기여:
발견 / 실패한 가설 / 유지보수 시간:
결정: 유지·수정·중단 / 다음 행동·담당·검토일:
```

Day 30/60/90 보고에는 위 관측과 함께 비교 가능한 기간, 달라진 제품 조건, 결측을 쓴다. Day 90에는 가장 도움 된 대상/자료, 실패한 채널, 사용자 피해·지원 부담, 실제 성과와 다음 30일 실험 최대 2개를 선택한다. **문서 작성 완료는 성장 실험 실행이나 제품 출시 완료가 아니다.**
