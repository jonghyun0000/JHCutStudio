# 엔진·입력·프록시 냉정한 감사 — 0.3 작업 시작점

이 문서는 0.2 소스를 직접 읽은 결과다. `MediaImporter.swift`, `TimelineRenderer.swift`, `TimelineCompositor.swift`, `ExportJob.swift`, `WaveformAnalyzer.swift`를 기준으로 한다. 기능 점수나 경쟁 제품과의 동등성을 증명하지 않는다. 아래 24개 항목은 서로 구분되는 실제 제약 또는 실패 위험이다.

| E01 | 높음 | 영상 코덱을 H.264 한 종류로 제한 | 흔한 SDR HEVC를 편집할 수 없다. 실제 HEVC 인코딩·디코딩·최종 출력 테스트 후 확장한다. |

## 0.3 엔진 결과 — 실제 실행 증거

개발용 분리 빌드에서 [호환성·프록시 검사 46/46](../Artifacts/Compatibility-8pIZSM/report.md), [기존 고급 편집 검사 16/16](../Artifacts/EngineProbe-W3j8aP/engine-checks.json)이 통과했다. 보고서 JSON에는 실행한 코어 dylib의 SHA-256이 있다. 이는 앱 최종 빌드의 결과로 자동 대체되지 않는다. 최종 앱과 동일한 코어 재검사는 아래의 `JHCUT_COMPAT_USE_EXISTING_CORE=1`로 실행하며 별도 결과를 남긴다.

- E01–E04: 실제 SDR H.264, HEVC, ProRes 422, ProRes 422 HQ를 각각 30프레임 인코딩·전체 디코딩했다. JPEG·HEIC의 회전 EXIF 6과 반전 2/7을 실제 픽셀로 검증했다. 이 8개 입력을 연속 배치한 8초 H.264 출력 240프레임을 끝까지 디코딩했고, 각 구간의 공유 렌더·출력 MAE는 0.00048–0.00297이었다.
- E05: ImageIO의 `ProfileName=sRGB`만으로 SDR를 판정하면 안 됨을 실제 무프로파일 JPEG/HEIC로 재현했다. JPEG의 ICC 또는 명시적 EXIF sRGB, PNG의 ICC/sRGB/cICP, HEIC의 ICC/NCLX 또는 명시적 EXIF sRGB 선언을 확인한다. 색 선언이 없는 JPEG/HEIC, 16비트 PNG, PQ/2020 태그 HEVC는 차단했다. 테스트 HEIC는 EXIF sRGB가 명시된 파일이다.
- E07–E09: 영상 첫 프레임 디코드, 모든 형식 설명 검사, 이미지 최대 1억 픽셀/축당 30,000픽셀 제한과 렌더용 최대4096픽셀 ImageIO 다운샘플을 구현했다. 기존 PNG 오버레이·한글 자막·속도·색 조정·페이드 검사16개가 유지됐다. 모든 손상 파일 종류나 극단 이미지 메모리 부하는 이번 검사로 증명하지 않았다.
- E10–E14: 영상 전용 H.264 프록시를 최대1280×720 안에 만들고 회전을 픽셀에 적용한다. 세로1080×1920 원본은 비율과 짝수 크기를 정확히 유지하기 위해396×704 프록시가 됐다. 원본29.97003fps,120프레임의 PTS와 유효 프레임 길이를 정확히 보존했다. AVAssetReader가 프레임 길이를 생략하는 정상 H.264는 다음 PTS와 마지막 트랙 끝으로 길이를 구하며 한 프레임만 미리 보관한다.
- 1.5배속·0.25초 source trim 상태의 원본/프록시 렌더5개 프레임 MAE는0.002699–0.002874였다. 타임라인23프레임에서 예상 원본41프레임을 양쪽 OCR이 모두 `FRAME 041`로 읽었다. 이 값은 실시간 재생의 드롭 프레임 검사나 모든 VFR 파일에 대한 증거가 아니다.
- 프록시 캐시는 버전·경로·파일 식별자·크기·수정시간·앞뒤64KiB 해시로 식별한다. 같은 URL의 `resourceValues`가 과거 수정시간을 반환하는 실패를 발견해 매번 새 파일시스템 속성을 읽도록 수정했다. 재시작 캐시 적중, 원본 변경 무효화, 잘린 캐시 거부, 용량 초과 거부, LRU, 사용 중 URL 고정, 취소 직후 부분 파일 없음, 사용자 파일 보존을 검증했다.
- 프록시는 영상에만 사용하며 오디오는 원본 트랙이다. `RenderPlan.usesProxyMedia`가 true인 계획은 ExportJob에서 출력 전에 거부한다(앱 통합 담당 변경). 프록시 사용 후 새 원본 계획으로1080×1920·60프레임·AAC 출력과 RMS0.07070을 검증했다.4/8/16Mbps 설정으로 실제 출력·디코딩했으며 비정상 비트레이트는 파일 생성 전에 거부했다. 설정값은 평균 목표 비트레이트이며 단순 화면의 실제 파일 비트레이트와 같다고 주장하지 않는다.
- E20/E22: 여러 비디오·오디오 트랙과 비정사각 픽셀은 보수적으로 거부한다. 선택 UI 및 clean aperture 처리의 일반 검증은 남았다.

E06 gain-map 감지는 구현했지만 실제 HDR gain-map 사진 fixture를 이번에 만들지 못했다. HEVC Main10·ProRes4444·Dolby Vision·카메라 Log·복잡한 HEIF 이미지 연결·광범위한 VFR·비영(非零) 시작 PTS·손상 파일 행렬은 미검증이다. “모든 HEVC/모든 iPhone 사진 호환”으로 표시하면 안 된다. HDR/불명확한 색공간 입력을 SDR로 자동 재표시하거나 톤 매핑하지 않는다.

E19, E21, E23–E24는 여전히 남고 E15·E18은 부분적으로 남는다. 프록시가 조합의 증분 갱신,4K/HDR 출력, 실시간 재생 성능을 해결한 것은 아니다. 캐시 지문은 전체 파일의 모든 바이트를 해시하지 않으므로 중간 바이트를 바꾸고 크기·시간까지 의도적으로 되돌린 변경을 탐지한다고 주장하지 않는다. 앱은 한 캐시 인스턴스로 생성을 직렬화하고 현재 계획의 URL을 고정해야 한다. 강제 프로세스 종료 시 남은 `.generating-*` 디렉터리의 자동 복구/정리는 아직 없다.

## E16·E17 수정과 측정

같은 프로브(`Tests/ScaleProbe.swift`)를 수정 전 코어와 수정 후 코어에 각각 링크해 측정했다. Apple M4 / Mac16,1 / 16GB / macOS27.0(26A428), 2초 합성 클립을 연속 배치한 단일 영상 트랙이다.

| 30 |60초|1.317초|0.055초|31|2|

수정 전 수치는 이 프로브로 새로 측정한 값이며, E17 항목에 있던 0.2의 8.9초와는 다른 프로젝트 형태라 직접 비교하지 않는다. 표의 시간은 `TimelineRenderer.build` 소요 시간이고 출력 인코딩은 포함하지 않는다.

패킹의 정확성은 픽셀과 PCM으로 확인했다. 순차 3클립의 지배 색 순서 R→G→B, 실제로 겹치는 오버레이 2클립이 레인 2개로 분리, 한 레인을 공유하는 오디오 클립의 개별 볼륨(RMS 0.28278 대 0.07070, 비율 4.00)과 1초 페이드 인 포락선 보존이다. 증거: `Artifacts/Perf-Final/Scale/scale-checks.json`.

### 패킹이 드러낸 실제 결함

`ClipEnvelopes.applyAudio`의 평탄 볼륨 경로가 `setVolume(_:at:)` 지점 하나만 기록했다. `AVMutableAudioMixInputParameters`는 연속한 볼륨 지점 사이를 보간하므로, 한 레인을 공유하게 되자 볼륨 1.0 클립이 다음 0.25 클립을 향해 서서히 줄어들었다. 측정 RMS 0.18418이 선형 램프 예측치 0.18428과 일치해 원인을 확정했다. 클립 자기 구간에 시작=끝인 평탄 램프를 명시적으로 고정해 해결했다. 클립마다 트랙이 따로일 때는 드러나지 않던 잠재 결함이다.

public actor ProxyCache {
    init(directory: URL? = nil, limitBytes: Int64 = 2_000_000_000)
    func cachedURL(for sourceURL: URL) throws -> URL?
    func generate(for sourceURL: URL,
                  progress: @escaping @Sendable (Double) -> Void = { _ in }) async throws -> URL
    func setProtectedURLs(_ urls: [URL])
    func sizeBytes() throws -> Int64
    func removeAll() throws  // 현재 사용 URL은 보존, 생성 중 호출은 거부

// Task.cancel()로 generate 취소. progress는 메인 액터 콜백이 아님.
