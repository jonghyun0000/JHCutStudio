# 5단계 미디어 시간·색상·안정화 정책

대상: JH CUT Studio / 2026-10-03. 검증 수치와 실행 경로는 AI-HANDOFF-PROGRESS-2026-10-02.md의 5단계 기록을 따른다.

## 입력과 출력

- 편집·합성·역재생·손떨림 분석의 작업 색공간은 SDR Rec.709다. 정상 importer의 코덱·색상·픽셀 비율·디코딩 검사를 우회하지 않는다.
- HDR 원본은 일반 편집에 직접 넣지 않는다. 메뉴의 **HDR → SDR 사본 가져오기…**가 Rec.2020 HLG 또는 PQ를 인식하고 Apple VideoToolbox의 명시적 10비트 색 변환기를 사용해 Rec.709 SDR 사본을 만든다. 태그만 바꾸는 처리는 하지 않는다.
- 색상 정보가 없거나 알려지지 않은 transfer/primaries/matrix 조합과 Log는 변환 전에 거절한다. Log를 HLG/PQ로 추측하지 않는다. 원본 파일은 변경하지 않는다.
- 변환기는 원본을 직접 읽는 HDRVideoConverter를 사용하고 VTPixelTransferSession의 목적 primaries/transfer/matrix를 모두 Rec.709로 지정한다. 색상 변환을 먼저 수행하며 BGRA8로 정밀도를 낮춘 뒤 H.264로 기록하며 트랙 회전 정보를 보존한다. 변환한 SDR 영상과 선택한 원본 오디오는 마지막 MP4 기록에서 H.264/AAC로 함께 출력한다. 색 변환 완료 후의 SDR 영상만 마지막 합성에 넣으며 videoComposition은 사용하지 않는다. importer로 결과를 다시 검사한다. 기본 합성기와 composition 내부의 소스 색정보 변경 경로는 픽셀 회귀에서 실패해 HDR 처리에서 제외했다. 이 경로에서 HDR→SDR 색 변환을 수행하는 근거는 [Apple 공식 문서의 SDR 변환 절](https://developer.apple.com/av-foundation/Incorporating-HDR-video-with-Dolby-Vision-into-your-apps.pdf)이다. 강한 PQ 하이라이트의 차이가 SDR에서 포화될 수 있다. HDR 보존 출력, Dolby Vision 동적 메타데이터 보존, 카메라 Log 색 변환은 지원하지 않는다.
- HDR 직접 변환기는 읽은 PTS/표시 구간을 SDR 중간 영상에 기록한다. 마지막 H.264/AAC 출력은 오디오의 실제 길이와 동기를 보존하도록 원본 오디오를 직접 사용한다. 중간 AAC를 잘라 passthrough로 결합하면 끝이 44ms(2112샘플) 짧아지는 사례 — AAC priming/edit list 처리 영향으로 추정 —가 재현되어 사용하지 않는다. SDR 원본을 기본 composition으로 다시 만드는 경로와 최종 타임라인 출력은 고정 출력 프레임 간격으로 샘플링된다. 모든 HDR 포맷의 VFR PTS 보존을 검증했다고 표현하지 않는다. 원본 시간 길이·오디오 위치와 컬러 변환을 검증하며, 타임라인 출력 허용 오차는 출력 한 프레임이다.
- 미지원 미디어는 원본을 보존하고 issue를 표시한다. 여러 오디오는 변환 시 하나를 선택한다. 변환을 취소하거나 문서·미디어 기준 경로·프로젝트가 바뀌면 결과를 적용하지 않고 새로 만든 미사용 사본을 정리한다. 기존 목적지 파일은 덮어쓰지 않는다.

## VFR 역재생

원본의 표시 PTS를 정렬하고 각 프레임을 `[PTS, 다음 PTS)`에 유지한다. 마지막 프레임 끝은 영상 트랙 끝이다. 이 구간과 선택 범위를 교차시킨 뒤 `출력 PTS = 선택 범위 끝 − 교차 구간 끝`, `출력 duration = 교차 구간 길이`로 저장한다. 선택 시작이 프레임 사이에 있어도 그 경계를 가로질러 유지되는 프레임을 포함한다. 한 프레임의 부분 구간도 처리한다.

비디오와 MP4 컨테이너 시간 단위는 요청·프레임 시간 단위들의 최소공배수다. 정확히 표현할 수 없으면 작업을 거절한다. 평균 FPS나 median frame duration으로 마지막 프레임 길이를 추측하지 않는다. 디코드 청크에 필요한 프레임이 빠지거나 기록기가 진행하지 못하면 사본 완료로 취급하지 않는다. AAC 소리는 선택한 구간의 PCM을 뒤집고 같은 파일에 기록한다. 역재생 사본 길이는 120초까지다.

## 손떨림 분석

- 경로의 시각 0은 요청 시작이 아니라 실제 첫 디코드 PTS다. 분석 선택 구간의 실제 끝(analyzedEnd)을 별도로 저장해 마지막 VFR 프레임의 긴 유지 시간 때문에 보정 전체가 누락되지 않도록 한다. 좌표는 트랙 회전 적용 전의 원본 디코드 좌표이며 x 오른쪽, y 위쪽, 회전 반시계 방향이다. 렌더러는 `sourceStart + timelineLocal × playbackRate`로 보정 경로를 읽는다. 트림·분할은 저장 경로를 재매개변수화하지 않는다.
- 신뢰도는 선택한 프레임 쌍 중 추정이 승인된 비율이다. 이는 화질 점수나 학습 모델 확률이 아니다. 타일 합의 비율 50% 미만, 과도한 이동·회전, 추정 실패는 거절한다. 신뢰도 50% 미만은 기본적으로 보정을 끄고 원본을 유지한다. 50~65% 미만은 기본 강도를 0.35로 제한한다. 재분석도 이 제한을 유지하고 사용자가 꺼 둔 상태를 보존한다.
- 고정 확대는 최대 1.25배다. 그 범위를 넘는 보정은 방향을 유지하면서 축소한다. 제한된 샘플 수와 신뢰도를 표시한다. 분석은 원본 구간 10분까지이며 더 긴 구간은 분할한다.
- 회전을 픽셀에 반영한 프록시는 원본 디코드 좌표와 다르다. 보정이 활성화된 클립은 미리보기도 원본을 사용한다. 보정을 끄면 프록시를 계속 사용할 수 있다. 이 정책은 미리보기와 출력의 좌표 일치를 우선하며, 보정 중 프록시 성능 이점은 제한된다.
- 롤링셔터, 모션 블러, 장면 전환, 피사체의 움직임은 별도 교정하지 않는다. UI에서 롤링셔터 미지원과 저신뢰 원본 유지·제한 상태를 안내한다.

## 평가 해석

Tests/MediaTimingProbe.swift는 비균등 PTS·부분 유지 프레임·NTSC 청크 경계·AAC 클릭·회전·실제 사본·합성 HLG/PQ 10비트 패치를 검사한다. 색상은 HLG/PQ 각 6개의 중성 명암 패치 출력 픽셀을 독립적인 메모리 내 10비트 VideoToolbox SDR 변환 결과와 비교하고, 원시 신호값을 그대로 SDR로 재태깅한 값과도 구별한다. 같은 Apple 변환 계열의 일치 검사이지 색상계 측정이나 Dolby Vision 인증은 아니다.

Artifacts/Stage5Copies/manifest.json의 네 파일은 사용자 원본에서 만든 해시 검증 사본이다. handheld/pan/저조도/피사체 분류는 로컬 시각 검사에서 정한 **후보**다. 실제 camera path의 정답은 없으며 잔여 움직임 지표는 팬·피사체·블러의 영향을 받는다. 합성 정답 경로의 개선율과 실제 촬영의 관측 수치는 반드시 분리한다. 확보되지 않은 실제 HDR 원본·특수 포맷은 미검증으로 남긴다.
