# 실제 iPhone 정확도 평가와 사람 검수 안내

2026-10-03 · 10단계. 사람 정답이 없는 실사 자료는 **평가 불가(unscored)** 입니다. 인식 결과가 그럴듯하거나 반복 실행이 통과한 것만으로 단어 정확도를 판단하지 않습니다.

## 준비한 자료

새 실행마다 Artifacts/Runs 아래 별도 Build/Outputs/로그를 만듭니다. test-real-accuracy.sh의 출력에 나오는 REVIEW-START.md에서 각 구간의 review.html을 찾을 수 있습니다. 페이지는 외부로 음성을 보내지 않으며, 같은 폴더의 listen.wav와 native-N.wav를 사용합니다. 사람이 페이지를 브라우저에서 열어 듣습니다.

| 영상 | 원본 시각 | 선정 근거 | 현재 상태 |
|---|---|---|---|
| IMG_0047.mov | 660~780초 | 기존 우선 검수 후보 | 언어·대사·소음 조건 미검수 |
| IMG_9211.mov | 480~600초 | 기존 우선 검수 후보, 523~531초 인식 누락 후보 포함 | 실제 대사·누락 여부 미검수 |
| IMG_0140.mov | 810~855초 | 과거 자동 VAD의 816~842.25초 말소리 후보 | 실제 발화 미확정 |

자동 VAD/ASR은 후보 선정 근거일 뿐 정답이 아닙니다. 조용한 말·배경 음악·소음·짧은 응답·겹친 발화가 실제로 포함되는지 사람 검수에서 분류합니다. 발화가 없는 영상은 비발화 대조군으로 유지하고 발화 자료 부족을 보고합니다. 3개 파일이 한국어·일본어·영어 모두를 대표한다고 주장하지 않습니다.

## 사람이 해야 하는 검수

1. 혼합 음성과 모든 원본 채널을 직접 듣습니다. 자동 초안을 먼저 보지 않고 받아쓰는 것을 권장합니다. 초안을 참고했다면 해당 항목을 표시합니다.
2. 초기의 전체 미검수 제외 행을 삭제하고, 선택 구간 전체를 대사(speech)·비발화(nonspeech)·평가 제외(excluded)로 빈틈과 겹침 없이 나눕니다. 빈 구간 표시 기능은 미검수 공백만 추가하며, 침묵이라고 추측하지 않습니다.
3. 실제로 들은 대사만 적습니다. 발음·말의 내용은 고치거나 추측하지 않습니다. 음악·노래·효과음만 있는 구간에는 대사를 적지 않습니다. 알아듣기 어려운 말이나 화자가 겹쳐 분리할 수 없는 발화는 사유와 함께 제외합니다. 현재 겹침 정책은 exclude입니다.
4. 모든 시각은 **원본 영상 초**입니다. 예를 들어 IMG_9211의 잘라낸 음성 3초는 원본 483초입니다. 페이지의 현재 시각 넣기 버튼은 이 이동을 반영합니다.
5. 검수자 이름, 대사 언어, 실제 청취·대사 확인과 전체 발화 구간 확인을 입력합니다. 시간도 직접 확인한 경우에만 시간 검수를 표시합니다. 문구 검수만으로 시작·끝 시각을 정답으로 간주하지 않습니다.
6. 정답 JSON을 저장합니다. 자동 미검수 사유를 그대로 둔 채 체크만 하면 저장·평가가 거부됩니다. 모든 제외 구간은 실제로 확인한 사유가 있어야 합니다. 프로그램은 사람의 확인을 기록하며, 실제 청취 자체를 인증하지는 못합니다.
7. 기존 정답을 수정하기 전 References/IPhone/Revisions/<segmentID>/<revisionID>.reference.json으로 보관합니다. 새 JSON을 References/IPhone/<segmentID>.reference.json에 넣습니다. 파일이 이미 있으면 덮기 전에 이전 버전을 보관하세요. 매 저장에는 새 revision UUID와 parent가 기록됩니다. 실행은 원래 정답을 읽기만 하고 원본 bytes/SHA를 reference-snapshot.json에 보존합니다.

사람이 독립적으로 확인한 대본이 인식 결과와 완전히 같아도 유효합니다. 자동 결과에서 2% 이상 수정해야 한다는 규칙은 없습니다. 단순 TXT/SRT는 검수자·범위·제외 정책을 담지 못하므로 이 회귀 도구에서는 정답으로 자동 채택하지 않습니다.

## 실행

프로젝트 폴더에서 실행합니다. 결과 폴더는 매번 새로 생성되고, 기존 결과는 덮지 않습니다.

```bash
bash Scripts/test-real-accuracy.sh
```

기본 정답 폴더는 References/IPhone입니다. 다른 폴더는 JHCUT_REFERENCE_DIR로 지정합니다. 인식 언어 기본 auto, 채널 기본 -1(자동)이며 JHCUT_ACCURACY_LANGUAGE=auto/ko/ja/en, JHCUT_ACCURACY_CHANNEL=-1..31로 명시할 수 있습니다. 원본에 채널이 없으면 실행이 거부됩니다.

검수된 최초 실행의 summary.json을 기준선으로 지정해 같은 조건으로 새 실행을 비교합니다.

```bash
JHCUT_ACCURACY_BASELINE="/absolute/path/to/previous/summary.json" bash Scripts/test-real-accuracy.sh
```

원본 hash/범위, 정답 bytes SHA, 모델/runtime SHA, 설정, 원본 채널 계획, 모드, 지표 정책이 같아야 비교합니다. 구현의 core SHA와 pipeline 버전은 별도 기록하므로 같은 조건에서 구현 개선을 비교할 수 있습니다. 정답을 수정했거나 모델·채널을 바꿨다면 새 기준선이 필요합니다. 기준선 파일 자체도 신뢰 가능한 보관본을 사용하세요.

## 평가 규칙과 결과

각 4구간에서 full / skip-conservative / skip-fast를 같은 모델·입력·고정 원본 채널 계획으로 두 번씩 실행합니다. 총 24개 인식 결과입니다. 재사용 체크포인트 없이 측정하며 VAD 시간과 인식 시간은 별도로 기록합니다. skip의 전달 음성 길이는 재인식/재시도 총량이 아니라 선정된 VAD 구간 길이입니다.

- CER: NFKC·소문자·문장부호 정규화 후 공백 제외 문자 오류율. 한국어 WER은 어절 단위여서 **띄어쓰기 영향을 받습니다**. 영어는 공백 단어, 일본어는 시스템 단어 분할을 사용합니다.
- 누락: 텍스트 유사도 0.5 이상 문장 대응에 실패한 정답 대사. referenceSpanID와 원본 시각이 사건에 기록됩니다. matchedReferenceShare는 이 문장 대응 비율이며 의미 이해나 정확한 단어 recall이 아닙니다.
- 과잉 자막: 사람이 비발화라고 확인한 구간에 완전히 들어오는 인식 자막 수. 대사/비발화 경계에 걸친 과잉을 모두 포착한다는 보장은 없습니다.
- VAD recall: 사람 발화 시간 중 VAD 후보의 합집합이 덮는 시간 비율. 중복 구간을 이중 계산하지 않습니다. 단어 복원율이 아니며 full 모드에는 해당 VAD 값이 없습니다.
- 시간 오차: 사람 시간 검수까지 완료한 대응 쌍의 시작/끝 절대 오차. p50은 짝수 표본에서 두 중앙값 평균, p95는 정렬 후 ceil(0.95×n)번째 최근접 순위입니다. 검수 전 또는 대응 쌍이 없으면 수치가 없습니다.
- 제외 안의 자막은 사건 기록을 남기고 채점에서 뺍니다. 제외 경계에 걸치는 자막은 텍스트를 추측 분할하지 않고 해당 실행을 unscored로 보류합니다. 전체 제외나 무정답도 unscored입니다. 사람이 확인한 비발화 대조군은 CER/WER 분모가 없어 수치 없이 과잉 자막 수만 냅니다.
- 긴 제한 문장 대응은 alignmentLimited로 표시합니다. CER/WER과 별도로 누락/시간 결과를 검토해야 합니다.

원본·정답 변경, 잘못된 범위/형식, 회귀 보류는 성공으로 처리하지 않습니다. 같은 인식 결과의 반복 안정성도 확인하지만 동일성이 곧 정확도는 아닙니다. summary.json, dataset-manifest.json, checks.json과 구간별 원음·ASR·정답 snapshot·검수 페이지가 함께 보존됩니다.

권장 임시 게이트는 CER 또는 WER **2%p 초과 악화**, 대응 정답 비율 **1%p 초과 하락**이면 hold_regression입니다. 60초 미만 발화 표본이나 제한 문장 대응은 수치가 좋아도 검토가 필요합니다. 절대 정확도 목표와 통계적 보장은 검수된 기준선 이후 정합니다. 아직 사람 정답이 없으면 이 게이트와 실사 정확도를 확정할 수 없습니다.

## 현재 검증의 한계

현재 실사 정답 검수는 미완료입니다. 테스트용 synthetic reference의 사람 이름/가짜 hash는 검수 도구와 채점 로직 검사용이며 실제 아이폰 정답이 아닙니다. 수작업 브라우저 재생·저장 흐름은 별도 확인이 필요합니다. 에이전트의 로컬 파일 브라우저 열기는 URL 정책으로 거부되어 자동 UI 검증을 하지 않았으며, 파일·스크립트·Swift 상호 검증을 사용합니다. 검수된 실사 수치가 나오기 전에는 10단계의 최종 완료 기준을 충족한 것으로 표시하지 않습니다.
