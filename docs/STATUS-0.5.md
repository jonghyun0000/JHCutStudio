## GUI에서 발견한 추가 문제와 수정

같은 실사 637클립 프로젝트에서 재생 중 화면 상태 확인이 61~82초 걸렸다. 프로파일링에서 플레이헤드의 `@Published` 변경이 편집기 전체 SwiftUI 갱신을 유발함을 확인하고, 별도 `PlaybackClock`을 시간 표시와 타임라인만 관찰하도록 분리했다. 선택된 클립이 없을 때 전체 클립을 찾던 불필요한 반복도 제거했다.

수정 후 같은 프로젝트의 ‘재생+상태 확인’은 0.894초, ‘일시정지+상태 확인’은 0.864초에 반환됐다. 정지 뒤 최종 위치 11초 14프레임이 후속 관찰에서 유지됐다. **이 시간은 UI 자동화 도구의 왕복 시간이며 버튼 입력 지연의 정밀 측정이 아니다.** `gui-playing-sample.txt`, `gui-playing-isolated-clock.txt`에 전후 프로파일을 보관했다. 최종 앱 재시작 후 0.5.0 표시, 영상 출력 버튼, 최근 출력 기록 UI를 확인했다.

## 자동 자막과 오디오

base 다국어 모델은 설치·해시 검증·실제 인식·자막 픽셀 출력까지 확인했다. small 선택/설치 UI는 있지만 추가 다운로드 승인은 아직 받지 않아 설치하지 않았다.

T7의 위 첫 두 파일에서 원본 30~60초 구간을 인식했다. 각각 자막 1개/12개가 생성됐고 처리 시간은 5.18초/2.10초였다. 첫 파일은 `RealSpeech/real-captions.jhcut` 및 `real-captions.mp4`로 출력했다. **대사·음악·잡음의 정답 라벨이 없으므로 인식 결과 생성만 확인한 것이며 CER/정확도 점수를 제공하지 않는다.** 문구는 교정 전 상태다.

LUFS는 48kHz K-weighting/400ms block/75% overlap/gating 구현이다. 기준 정현파에서 -23.0103 LUFS를 측정했다. 겹친 과도음 입력 +11.60dBFS를 샘플 피크 -1.50dBFS로 제한하고 최종 CAF 디코딩에서 full-scale clipping sample 0개를 확인했다. 같은 파일의 4배 재표본화 피크 추정은 -0.49dBFS였다. 따라서 이 기능을 **-1.5dBTP 보장 리미터 또는 인증된 계측기라고 부르면 안 된다.** 믹스 음성 강조는 전체 믹스의 간단한 EQ/압축/expander이며 개별 대사 AI 잡음 제거가 아니다.

## 저장 장애·배포 범위

128MB의 자체 생성 APFS 디스크 이미지에 저장한 사본으로 실제 공간 고갈, 저장 프로세스 SIGKILL, 볼륨 분리, 재연결 후 출력을 시험했다. 정상 문서/백업/복구본 보존과 재출력을 확인했다. 사용자 T7나 다른 볼륨을 분리하지 않았고, 이 결과로 실제 ExFAT 케이블 뽑기·컨트롤러 장애까지 검증했다고 주장하지 않는다.

`Scripts/package-release.sh`는 명시적으로 제공한 Developer ID와 공증 프로필로 패키징하는 절차다. 이 Mac에는 해당 인증서가 없어 실행하지 않았다. 앱은 로컬 ad-hoc 서명 상태다. 공증, 다른 Mac/지원 OS 설치 검증, 업데이트/롤백, 사용자가 동의한 크래시 수집은 미완료다.
